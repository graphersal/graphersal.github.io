The Graphersal Documentation

TCK Compliance

Graphersal's GQL is measured against the openCypher TCK (Technology Compatibility Kit): Gherkin scenarios that each set up a graph, run one query and state the exact expected result, side effects or error. They exercise the Cypher compatibility forms that gql() accepts (CREATE, MATCH ... RETURN, WITH, UNWIND, ...) with Neo4j's semantics, so the kit works as a ready-made differential test. It serves three purposes:

  1. Compliance measure: what passes, what does not, and why.
  2. Regression gate: a test case that passed must keep passing; cargo test fails otherwise.
  3. Backlog generator: the report ranks the missing constructs and lists every wrong behaviour.

Graphersal's GQL is not a Cypher implementation; the TCK measures how far its compatibility forms agree with the behaviour the kit specifies.

The kit

  • Pinned version: openCypher TCK release 2024.3 (commit 677cbafabb8c3c5eed458fd3b1ec0daec8d67d23), vendored unmodified under crates/graphersal/tests/opencypher/ (features/, the named graphs in graphs/, its licence and notice). The directory's README.md records the upgrade procedure. A test case is a scenario, or one Examples row of a scenario outline.
  • Runner: the integration test target crates/graphersal/tests/opencypher_tck.rs (feature gql), with its harness in crates/graphersal/tests/opencypher/harness/. Every case runs on a fresh graph through the Rust GQL API: the setup queries (having executed, the named graphs) run through gql()'s own writes, the query runs with its parameters, then its rows, its side effects (a state diff) and its error are compared. Every query runs under resource limits and a wall-clock guard.
  • Gate: crates/graphersal/tests/opencypher/baseline.toml lists every in-scope case that does not pass yet, with its class and a one-line reason.

Out of scope

Some cases are excluded from the scope: they are not run, get the class excluded, have no baseline entry and are in no total or percentage. They are listed by case id, grouped by reason, in crates/graphersal/tests/opencypher/harness/scope.rs (ids, never tags or content, so a case that a kit upgrade adds is never excluded silently). Merely unimplemented constructs are never excluded: they stay missing, the backlog.

  • upstream-ignore: the one scenario that the kit itself marks @ignore.
  • w21-property-kinds (a deliberate deviation, user decision): a list of maps is a valid property value in Graphersal, where Neo4j raises a TypeError (Semantics).
  • parameter-at-compile-time (a deliberate deviation, user decision): a negative or non-integer $parameter of SKIP / LIMIT is refused when the query is compiled, since parameters are bound then; the kit expects the SyntaxError at runtime. The user sees the same thing, an error before any row (Semantics).

Every difference from Neo4j, also those the kit has no case for, is listed on Semantics.

The deliberate deviations run in a guard test (deviation_cases_still_deviate): it fails when one of them passes, so it moves back into scope. id() (an integer in Neo4j, a string id here) does not occur in the pinned kit.

Classes

ClassMeaning
passevery expectation holds: rows (and their order where stated), column names, side effects, the error type and phase
missingthe query uses a construct that gql() refuses or does not support yet (GQLSTATUS 0A000); the report ranks the constructs
setupa setup step (having executed, a named graph, a parameter value) does not run, usually for the same reason
excludedout of the scope (above): not run, in no total
wrong_resultthe rows differ
wrong_columnsthe column names differ
wrong_side_effectsthe side effects differ, or a failed query changed the graph
wrong_erroran error was expected and another one (type or phase), or none, came
unexpected_erroran error where a result was expected
timeouta time or resource budget of the harness fired
panica panic was caught (a rule-1 violation, top priority)

The headline groups them: Unsupported = missing + setup; Wrong behaviour of supported constructs = the seven classes from wrong_result to panic. An unimplemented construct is fine; a supported construct must behave as the kit specifies, unless a user decision says otherwise (then the case is excluded with its reason and documented as a difference from Neo4j). The wrong-behaviour count is driven to 0.

Errors match by type and phase only, never by the detail text. The phase comes from where the error arose: compile time is an error of parsing, binding or planning, before the traversal runs; runtime is an error while it runs.

Running and regenerating

# Run the kit (also part of the plain `cargo test --package graphersal --features script,io,display,serde,persist,gql`)
cargo test --package graphersal --features script,io,display,serde,persist,gql --test opencypher_tck

# Rewrite the baseline AND the generated blocks of this page after intended changes; review the diff like code
OPENCYPHER_UPDATE_BASELINE=1 cargo test --package graphersal --features script,io,display,serde,persist,gql --test opencypher_tck

Every run prints a summary to stderr and writes the full report to target/opencypher-report.md: the headline, the per-directory table, the exclusions with their ids, the full wrong-behaviour list by class, the missing constructs ranked by the number of cases they block, the setup failures by reason and the baseline class changes. OPENCYPHER_DETAILS=1 prints one line per in-scope case that does not pass; OPENCYPHER_LANES=<n> sets the number of parallel lanes (default: one per core).

The test fails when:

  • a case that is not in the baseline does not pass (a regression);
  • a case in the baseline passes now, no longer exists or is excluded (the entry is stale; remove it in the same change);
  • an id of the scope table does not exist, an @ignore case is not in it, or a deliberate deviation passes now (scope_table_is_consistent, deviation_cases_still_deviate);
  • a generated block of this page (scope, headline, directories, excluded) differs from what the run computes. Only trailing whitespace is ignored.

A case still failing under another class than recorded is reported, not failed. GRAPHERSAL_TEST_STORAGE=forwarding runs the whole kit on a storage that is not TraversalGraph (the Forwarding wrapper of graphersal-storage-tests): the same gate against the same baseline and page, it additionally fails when a case changes class, never rewrites either and writes target/opencypher-report-forwarding.md.
