The Graphersal Documentation

GQL Conformance

This page lists which parts of ISO/IEC 39075 (GQL) gql() supports, in the style of the conformance appendices that GQL implementations publish. It is maintained by hand together with the code; when a construct lands, its row moves here in the same change.

GQL names its optional features with identifiers such as G036 (graph pattern features), GQ.. (query features), GE.. (expressions), GF.. (functions), GA.. (additional behaviour), GB.. (lexical), GL.. (literals), GH.. (other). This page cites only those identifiers and short descriptive names of our own; it does not reproduce the standard. An identifier marked (provisional) could not be checked against the standard text yet and may be corrected.

How far the Cypher compatibility forms agree with Neo4j's behaviour is measured against the openCypher TCK: TCK Compliance.

Status: supported, partial (what is missing is named), not yet (planned), no (refused for good; see Refused Constructs).

Implementation-defined choices

Where the standard leaves a choice to the implementation, gql() makes this one (Neo4j's, where it has one):

TopicChoice
NULL in ORDER BYlast ascending, first descending
order of values of different typesmap, vertex, edge, list, date/time, UUID, string, boolean, number, vector, NULL
row order without ORDER BYunspecified
item order of a pattern comprehensionunspecified: the order the matches are found, which depends on the plan
item order of COLLECT { }the order of the body's rows: its ORDER BY when it has one, unspecified otherwise
UNION operands with the same column names in another orderaccepted, matched by name; the result has the first operand's column order (provisional)

a CALL body that imports nothingstill run once per incoming row; its rows are not cached
the RETURN items of a projecting COUNT { } bodynot evaluated: the rows are counted, an expression that would fail raises no error (a deviation, Semantics)

Differences from the standard

Where ISO GQL and Neo4j disagree and the openCypher TCK measures the Neo4j behaviour, gql() follows Neo4j in these places (user decision, stage 3f):

TopicISO GQLgql()
= / <> / IN / simple CASE between values of different kindsnot comparable= FALSE, <> TRUE (1 = '1', [1] = 1, 1 IN ['1']); the orderings < .. >= stay NULL (Semantics)
< <= > >= on two listsnot comparablelexicographic, three-valued
a float divided by zero22012IEEE 754: Infinity, -Infinity or NaN; an integer divided by zero stays 22012
NaN in a comparison(no NaN arises: every division by zero is 22012)never equal (NaN = NaN FALSE), every ordering against a number FALSE

The deliberate differences from Neo4j are listed on Semantics.
