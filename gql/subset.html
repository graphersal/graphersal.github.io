The Graphersal Documentation

The Supported Subset

This page lists what gql() accepts in this version, construct by construct, each with a runnable example and, where it is natural, its Gremlin twin. Everything not listed here is an error that says so (Not supported yet at the end, Refused Constructs for what will never be supported).

The shape of a query

[ clauses, in any order and number:
  [OPTIONAL] MATCH <pattern> [, <pattern> ...] [WHERE <condition>]
  LET <name> = <expr> [, ...]
  FILTER [WHERE] <condition>
  FOR <name> IN <list> [WITH ORDINALITY <name> | WITH OFFSET <name>]
  UNWIND <list> AS <name>                     -- Cypher spelling of FOR
  WITH [DISTINCT] <item> [AS <name>], ...     -- or WITH *; Cypher
       [ORDER BY ...] [OFFSET <n>] [LIMIT <n>] [WHERE <condition>]
  [OPTIONAL] CALL [(<name>, ...) | (*)] { <query> }   -- a subquery run for each row
  [OPTIONAL] CALL <folder>.<name>(<arg>, ...)          -- a saved query run for each row
       [YIELD <column> [AS <name>], ... [WHERE <condition>]]
  INSERT <pattern> [, <pattern> ...]          -- Cypher spelling: CREATE; creates per row
  SET <item> [, ...]  /  REMOVE <item> [, ...] -- change properties and labels per row
  [DETACH | NODETACH] DELETE <expr> [, ...]   -- removes per row; NODETACH is the default
  MERGE [<name> =] <pattern>                  -- Cypher; finds or creates one pattern per row
       { ON CREATE SET <item> [, ...] | ON MATCH SET <item> [, ...] }   -- any number, any order ]
RETURN [DISTINCT] <item> [AS <name>], ...     -- or RETURN *; items may aggregate
                                              -- (mandatory unless the last clause writes;
                                              -- FINISH ends a query without a result)
[ORDER BY <expr> [ASC | DESC], ...]
[OFFSET <n>]                                  -- Cypher alias: SKIP
[LIMIT <n>]
[ UNION [ALL | DISTINCT] <clauses> RETURN ... [ORDER BY ...] [OFFSET ..] [LIMIT ..] ]   -- any number
[ NEXT <the same again: clauses, RETURN, UNION ...> ]                                   -- any number
[;]

-- or a standalone call of a saved query, the whole query:
CALL <folder>.<name>[(<arg>, ...)] [YIELD * | YIELD <column> [AS <name>], ... [WHERE <condition>]]

A pattern is a path of node and edge patterns, optionally named (p = (a)-->(b)); an edge may carry a quantifier (-[:knows]->{1,3}), and so may a parenthesized part of the path (((x)-[:knows]->(y)){1,3}, a quantified path pattern). A query usually starts with MATCH, but it may start with any clause, or with RETURN alone (Queries without MATCH). Queries ending in RETURN combine with UNION and continue with NEXT (UNION and NEXT); NEXT binds looser than UNION. A CALL runs a whole query of that shape for each row (CALL subqueries), and CALL folder.name(..) a saved query of the graph's catalog (Calling saved queries). INSERT creates nodes and edges once per row, SET / REMOVE change them, DELETE removes them and Cypher's MERGE finds or creates them; a query whose last clause writes may end there and returns no rows (Writing with GQL).

Keywords are case-insensitive (match, Match, MATCH); variables, labels and property keys are case-sensitive. The words ISO GQL lists as non-reserved (FIRST, LAST, LABELED, SHORTEST) keep their meaning where the grammar expects them (NULLS FIRST, IS LABELED) and are names everywhere a variable can stand: WITH [1, 2] AS first RETURN first. Line breaks are whitespace, so a query may span lines. Comments are // ..., /* ... */ and the GQL -- ... (the -- rule).

g.gql("match (n:person) where n.age > 30 return n.name as name order by name desc").to_list()   // #{"name": "peter"}, #{"name": "josh"}

MATCH

MATCH takes one or more patterns separated by commas. A variable written twice is the same element: that is how patterns join. Several MATCH clauses in a row combine the same way.

g.gql("MATCH (a)-[:knows]->(b), (b)-[:created]->(s) RETURN a.name AS a, s.name AS s ORDER BY s").to_list()   // #{"a": "marko", "s": "lop"}, #{"a": "marko", "s": "ripple"}
g.gql("MATCH (a)-[:knows]->(b) MATCH (b)-[:created]->(s) RETURN b.name AS b, s.name AS s ORDER BY b, s").to_list()   // #{"b": "josh", "s": "lop"}, #{"b": "josh", "s": "ripple"}

Patterns that share no variable form a Cartesian product: every combination of their matches.

g.gql("MATCH (a:person), (s:software) WHERE a.age > 32 RETURN a.name AS a, s.name AS s ORDER BY a, s").to_list()   // #{"a": "peter", "s": "lop"}, #{"a": "peter", "s": "ripple"}

Node patterns

FormMatches
()any vertex, unnamed
(n)any vertex, bound to n
(n:person) or (n IS person)a vertex with the label person
(n:person {name: 'marko'})... whose name equals 'marko'
(n:person WHERE n.age > 30)... for which the condition is TRUE
g.gql("MATCH (p:person {name: 'marko'})-->(x) RETURN x.name AS x ORDER BY x").to_list()   // #{"x": "josh"}, #{"x": "lop"}, #{"x": "vadas"}
g.gql("MATCH (p:person WHERE p.age < 30) RETURN p.name AS name ORDER BY name").to_list()   // #{"name": "marko"}, #{"name": "vadas"}
g.v().has_label("person").has("age", P.lt(30)).values("name").order().to_list()   // "marko", "vadas"

An inline property map {k: v} is the same as WHERE n.k = v: a property that is missing or NULL never matches.

Edge patterns

FormAbbreviatedMatches
-[e:T]->-> (Cypher -->)an edge pointing right
<-[e:T]-<- (Cypher <--)an edge pointing left
-[e:T]-- (Cypher --)an edge in either direction
<-[e:T]-><-> (Cypher <-->)an edge in either direction (same as -[e]-)

The brackets take the same parts as a node: a variable, a label expression after : or IS, an inline property map and a WHERE condition. Graphersal edges are always directed, so "either direction" means "pointing left or right"; a self-loop matches once (Semantics).

g.gql("MATCH (a)-[e:created]->(s:software) WHERE e.weight >= 0.4 RETURN a.name AS who, s.name AS what, e.weight AS w ORDER BY w DESC, who").to_list()
// #{"w": 1.0, "what": "ripple", "who": "josh"}, #{"w": 0.4, "what": "lop", "who": "josh"}, #{"w": 0.4, "what": "lop", "who": "marko"}
g.gql("MATCH (s:software)<-[:created]-(p) RETURN s.name AS sw, p.name AS author ORDER BY sw, author").to_list()
// #{"author": "josh", "sw": "lop"}, #{"author": "marko", "sw": "lop"}, #{"author": "peter", "sw": "lop"}, #{"author": "josh", "sw": "ripple"}
g.gql("MATCH (a)-[:knows]-(b) RETURN a.name AS a, b.name AS b ORDER BY a, b").to_list()
// #{"a": "josh", "b": "marko"}, #{"a": "marko", "b": "josh"}, #{"a": "marko", "b": "vadas"}, #{"a": "vadas", "b": "marko"}
g.gql("MATCH (a {name: 'marko'})-(b) RETURN b.name AS b ORDER BY b").to_list()   // #{"b": "josh"}, #{"b": "lop"}, #{"b": "vadas"}
g.v().has("name", "marko").both().values("name").order().to_list()   // "josh", "lop", "vadas"

Patterns chain: (a)-[..]->(b)-[..]->(c) is a path of two hops, and the same variable may close a cycle.

g.gql("MATCH (a:person)-[:knows]->(b)-[:created]->(s) RETURN a.name AS a, b.name AS b, s.name AS s ORDER BY b, s").to_list()
// #{"a": "marko", "b": "josh", "s": "lop"}, #{"a": "marko", "b": "josh", "s": "ripple"}
g.v().has_label("person").as("a").out("knows").as("b").out("created").as("s").select("a", "b", "s").by("name").to_list()
// #{"a": "marko", "b": "josh", "s": "ripple"}, #{"a": "marko", "b": "josh", "s": "lop"}
g.gql("MATCH (a)-[:created]->(s)<-[:created]-(b) RETURN a.name AS a, b.name AS b, s.name AS s ORDER BY s, a, b").to_list()
// josh/marko, josh/peter, marko/josh, marko/peter, peter/josh, peter/marko, all on "lop"

The last query never pairs a person with themselves: both edges would be the same edge, and a MATCH binds every edge at most once (trail semantics).

Quantified edges

A quantifier after an edge pattern repeats the edge: (a)-[:knows]->{1,3}(b) matches a path of one to three knows edges from a to b, every node in between unnamed. It applies to full and abbreviated edges (->{2}) in every direction.

QuantifierRepeats the edgeCypher spelling (alias)
{m,n}m to n times[*m..n]
{n}exactly n times[*n]
{m,}at least m times[*m..]
{,n}0 to n times
*0 or more times, {0,}
+1 or more times, {1,}[*] (Cypher's lower bound is 1)
1 to n times, {1,n}[*..n]
never: no match[*m..n] with m > n, [*..0]

A GQL lower bound above the upper bound ({3,1}) is a syntax error; the Cypher spelling of the same interval ([*3..1]) is empty and matches nothing, as in Neo4j.

A lower bound of 0 includes the zero-length match, where b is a itself. The edges of one match are all different (trail), so an unbounded quantifier ends on every finite graph (Semantics). The Gremlin twin is a repeat() with emit() and times():

g.gql("MATCH (a {name: 'marko'})-[:knows|created]->{1,2}(b) RETURN b.name AS b ORDER BY b").to_list()
// josh, lop, lop, ripple, vadas
g.v().has("name", "marko").repeat(__.out("knows", "created")).emit().times(2).values("name").order().to_list()
// "josh", "lop", "lop", "ripple", "vadas"
g.gql("MATCH (a {name: 'marko'})->{2}(b) RETURN b.name AS b ORDER BY b").to_list()   // #{"b": "lop"}, #{"b": "ripple"}
g.v().has("name", "marko").repeat(__.out()).times(2).values("name").order().to_list()   // "lop", "ripple"
g.gql("MATCH (a {name: 'marko'})->{0,1}(b) RETURN b.name AS b ORDER BY b").to_list()   // josh, lop, marko, vadas
g.v().has("name", "marko").emit().repeat(__.out()).times(1).values("name").order().to_list()   // "josh", "lop", "marko", "vadas"
g.gql("MATCH (a {name: 'marko'})-[:knows]->{1,2}(b)-[:created]->(s) RETURN b.name AS b, s.name AS s ORDER BY b, s").to_list()
// #{"b": "josh", "s": "lop"}, #{"b": "josh", "s": "ripple"}

The variable of a quantified edge is a group variable: after the pattern it is the list of the edges of the match, in the written order ([] for a zero-length match). Inside its own brackets (-[e WHERE e.weight > 0.5]->{1,2}) it is the single edge of each repetition, so the condition tests every edge:

g.gql("MATCH (a {name: 'marko'})-[e]->*(b) RETURN b.name AS b, size(e) AS hops ORDER BY hops, b").to_list()
// marko 0, josh 1, lop 1, vadas 1, lop 2, ripple 2
g.gql("MATCH (a {name: 'marko'})-[e:knows|created WHERE e.weight > 0.5]->{1,2}(b) RETURN b.name AS b, e AS edges ORDER BY b").to_list()
// #{"b": "josh", "edges": [e[2][1-knows->4]]}, #{"b": "ripple", "edges": [e[2][1-knows->4], e[4][4-created->5]]}
g.v().has("name", "marko").repeat(__.out_e("knows", "created").has("weight", P.gt(0.5)).in_v()).emit().times(2).values("name").order().to_list()
// "josh", "ripple"

To repeat more than one edge, put the chain in parentheses and quantify it: a quantified path pattern.

Quantified path patterns

A parenthesized path pattern ( <chain> [WHERE <condition>] ) with a quantifier after its ) repeats the whole chain, its nodes, edges and conditions included: (a) ((x)-[:created]->(s)<-[:created]-(y)){1,2} (b) walks from a to b over one or two "created the same software" hops. It takes every quantifier of a quantified edge ({m,n}, {n}, {m,}, {,n}, *, +) and also ? (0 or 1 times); without a quantifier it matches exactly once.

  • The outer nodes merge with the body. The node written before the group is the first node of the first iteration, the node after it the last node of the last iteration, and consecutive iterations join end to start: (a) ((x)-->(y)){1,3} (b) binds a = the first x and b = the last y. Where the text has no node next to the group (at the start or end of the path, or between two groups), an anonymous one stands. After zero iterations ({0,n}, *, ?) the two outer nodes are the same node.
  • Body variables are group variables. With a quantifier other than ?, every variable inside the body is, after the pattern, the list of its nodes or edges, one per iteration in walk order, like the variable of a quantified edge. Read the list (size(x), [n IN x | n.name], RETURN x), not a property of it: x.name outside the body is an error. With ? or without a quantifier the body variables are single values; with ? they are NULL when the part matched nothing (Semantics).
  • The body condition runs in every iteration. The WHERE before the closing parenthesis, and the inline maps and WHEREs of the body's elements, test each iteration's elements, and read only the body's variables, parameters and values; test an outer variable in the WHERE of the MATCH clause.
  • Trail holds across iterations. No edge is bound twice in one match, across the iterations, the body's edges and the other edges of the clause.
g.gql("MATCH (a {name: 'marko'}) ((x)-[e:knows|created]->(y)){1,2} (b) RETURN b.name AS b, size(e) AS hops ORDER BY hops, b").to_list()
// josh 1, lop 1, vadas 1, lop 2, ripple 2
g.gql("MATCH (a {name: 'marko'}) ((x)-[:knows|created]->(y)){1,2} (b) RETURN [n IN x | n.name] AS xs, [n IN y | n.name] AS ys ORDER BY ys").to_list()
// #{"xs": ["marko"], "ys": ["josh"]}, #{"xs": ["marko", "josh"], "ys": ["josh", "lop"]}, #{"xs": ["marko", "josh"], "ys": ["josh", "ripple"]}, #{"xs": ["marko"], "ys": ["lop"]}, #{"xs": ["marko"], "ys": ["vadas"]}
g.gql("MATCH (a:person) ((x)-[:created]->(s)<-[:created]-(y)){1,2} (b) RETURN DISTINCT a.name AS a, b.name AS b ORDER BY a, b").to_list()
// josh/marko, josh/peter, marko/josh, marko/peter, peter/josh, peter/marko
g.gql("MATCH (a:person) ((x)-[:knows|created]-(y) WHERE y.age > x.age){1,3} (b) RETURN a.name AS a, b.name AS b, size(y) AS steps ORDER BY a, b").to_list()
// #{"a": "marko", "b": "josh", "steps": 1}, #{"a": "vadas", "b": "josh", "steps": 2}, #{"a": "vadas", "b": "marko", "steps": 1}
g.gql("MATCH (p:person {name: 'josh'}) ((x)-[:created]->(s) WHERE s.lang = 'java')? (q) RETURN s.name AS project, q.name AS last ORDER BY project").to_list()
// #{"last": "lop", "project": "lop"}, #{"last": "ripple", "project": "ripple"}, #{"last": "josh", "project": ()}
g.gql("MATCH ((x:person)-[:created]->(s) WHERE s.name = 'ripple') RETURN x.name AS who").to_list()   // #{"who": "josh"}

The Gremlin twin is a repeat() of the body's steps; the second-to-last query is a filter on the body run in every iteration:

g.v().has_label("person").as("a").repeat(__.out_e("created").in_v().in_e("created").out_v()).emit().times(2).simple_path().as("b").select("a", "b").by("name").dedup().to_list()
// the same six pairs (simple_path() stands in for trail here)

A quantified path pattern stands wherever a pattern does: in MATCH and OPTIONAL MATCH, in EXISTS { }, COUNT { } and COLLECT { }, in a pattern comprehension and in a Cypher pattern predicate (which names no new variable, so its body stays anonymous):

g.gql("MATCH (p:person) RETURN p.name AS p, [(p) ((x)-[:created]->(s)<-[:created]-(y)){1,2} (q) | q.name] AS co ORDER BY p").to_list()
// josh [peter, marko], marko [peter, josh], peter [josh, marko], vadas []
g.gql("MATCH (p:person) WHERE EXISTS { (p) ((x)-[:knows]->(y)){1,3} (q:person {name: 'josh'}) } RETURN p.name AS p").to_list()   // #{"p": "marko"}
g.gql("MATCH (p:person) WHERE (p) (()-[:knows]->()-[:created]->()){1} RETURN p.name AS p").to_list()   // #{"p": "marko"}

Not yet supported inside the body (each refused with GQLSTATUS 0A000 and a help line naming the rewrite): a nested parenthesized path pattern, a quantified edge, a path variable (p = goes on the whole path), a path mode or search prefix, several comma-separated patterns or a union (|), a body without an edge, a variable written twice in one body, a variable bound outside the body written again inside it, a condition reading an outer variable, and a subquery. A variable inside a quantified body must be a new name (42002).

g.gql("MATCH (a) (((x)-->(y)){2})+ (b) RETURN b")   // error: a parenthesized path pattern nested in another one is not yet supported
g.gql("MATCH (a) ((x)-->(y)-->(z)){1,3} (b) RETURN b.name AS b ORDER BY b").to_list()   // #{"b": "lop"}, #{"b": "ripple"}
g.gql("MATCH (a) ((x)-->(y))+ (b) RETURN x.name")   // error: `x` is a group variable of the quantified path pattern

Path variables

p = <path pattern> names the whole path. RETURN p returns it as a path value (the alternating vertices and edges, the same value as Gremlin's path(); Result Shape), and path_length(p) (Cypher length(p)) is its number of edges. A quantified edge or path pattern contributes all its edges and the vertices in between.

g.gql("MATCH p = (a {name: 'marko'})-[:knows]->(b)-[:created]->(s) RETURN p, path_length(p) AS len ORDER BY s.name").to_list()
// #{"len": 2, "p": [v[1], e[2][1-knows->4], v[4], e[3][4-created->3], v[3]]}, #{"len": 2, "p": [v[1], e[2][1-knows->4], v[4], e[4][4-created->5], v[5]]}
g.v().has("name", "marko").out_e("knows").in_v().out_e("created").in_v().path().to_list()
// [v[1], e[2][1-knows->4], v[4], e[4][4-created->5], v[5]], [v[1], e[2][1-knows->4], v[4], e[3][4-created->3], v[3]]
g.gql("MATCH p = (a {name: 'marko'})->{1,2}(b) RETURN b.name AS b, length(p) AS len ORDER BY len, b").to_list()
// josh 1, lop 1, vadas 1, lop 2, ripple 2

A path is a value: it compares (p = q), sorts, groups and goes into collect_list(). The Cypher functions nodes(p) and relationships(p) return its vertices and its edges as lists (Lists, elements and paths):

g.gql("MATCH p = (a {name: 'marko'})-[:knows]->(b) RETURN nodes(p) AS n, relationships(p) AS r ORDER BY b.name").to_list()
// #{"n": [v[1], v[4]], "r": [e[2][1-knows->4]]}, #{"n": [v[1], v[2]], "r": [e[0][1-knows->2]]}
g.v().has("name", "marko").out_e("knows").in_v().path().to_list()
// [v[1], e[2][1-knows->4], v[4]], [v[1], e[0][1-knows->2], v[2]]

Label expressions

After : or IS, on nodes and edges:

ExpressionMeans
Ahas the label A
A&Bhas both (Cypher :A:B)
A|Bhas at least one
!Adoes not have A
%has any label (the label set is not empty)
(...)grouping, as in A&(B|C)

A vertex tests its label set; an edge has exactly one label.

g.gql("MATCH (n:person|software) RETURN n.name AS name ORDER BY name LIMIT 3").to_list()   // #{"name": "josh"}, #{"name": "lop"}, #{"name": "marko"}
g.gql("MATCH (n:!person) RETURN n.name AS name ORDER BY name").to_list()   // #{"name": "lop"}, #{"name": "ripple"}
g.v().not(__.has_label("person")).values("name").order().to_list()   // "lop", "ripple"
g.gql("MATCH (n IS person&!software) RETURN n.name AS name ORDER BY name").to_list()   // josh, marko, peter, vadas

In expressions the same test is v IS [NOT] LABELED <label expression> (Cypher: v:A):

g.gql("MATCH (n) WHERE n IS LABELED software RETURN n.name AS name ORDER BY name").to_list()   // #{"name": "lop"}, #{"name": "ripple"}
g.gql("MATCH (n) WHERE n:software RETURN n.name AS name ORDER BY name").to_list()   // #{"name": "lop"}, #{"name": "ripple"}

WHERE

WHERE after a MATCH clause (or inside a node or edge pattern) keeps the rows for which the condition is TRUE; FALSE and NULL drop the row (three-valued logic). It may read every variable of its MATCH clause and of the clauses before it.

g.gql("MATCH (a:person), (b:person) WHERE a.age < b.age AND a.name STARTS WITH 'm' RETURN a.name AS a, b.name AS b ORDER BY b").to_list()
// #{"a": "marko", "b": "josh"}, #{"a": "marko", "b": "peter"}

EXISTS and pattern predicates

An EXISTS subquery tests whether a pattern matches: it is TRUE when its body has at least one match for the row and FALSE otherwise, never NULL. Three forms mean the same:

EXISTS { MATCH <pattern> [, <pattern> ...] [WHERE <condition>] [MATCH ...] }
EXISTS { <pattern> [, <pattern> ...] [WHERE <condition>] }
EXISTS ( ... )                                -- either body in parentheses
(a)-[:knows]->(b)                             -- Cypher pattern predicate: a pattern where a condition stands

The body reads the variables bound before it (they are imported: p inside is the row's p), and the variables it binds itself stay inside it. A pattern predicate is EXISTS { <pattern> } written without the keyword; it must not name a new variable (write EXISTS { MATCH .. } to name one), and it stands only where a condition does: a WHERE or FILTER condition (also under NOT, AND, OR, XOR), the WHERE of a comprehension and a WHEN of a searched CASE. Anywhere else (a RETURN column, a function argument, a LET value) it is a syntax error (42001), as in Neo4j: write EXISTS { .. }, COUNT { .. } or a pattern comprehension there. The Gremlin twins are where(__..) and not(__..), and the "who has no ..." question runs exactly as its twin:

g.gql("MATCH (p:person) WHERE NOT EXISTS { (p)-[:created]->() } RETURN p.name AS name ORDER BY name").to_list()   // #{"name": "vadas"}
g.gql("MATCH (p:person) WHERE NOT (p)-[:created]->() RETURN p.name AS name ORDER BY name").to_list()   // #{"name": "vadas"}
g.v().has_label("person").not(__.out("created")).values("name").to_list()   // "vadas"
g.gql("MATCH (p:person) WHERE EXISTS { MATCH (p)-[:created]->(s) WHERE s.name = 'ripple' } RETURN p.name AS name").to_list()   // #{"name": "josh"}
g.v().has_label("person").where(__.out("created").has("name", "ripple")).values("name").to_list()   // "josh"
g.gql("MATCH (a:person), (b:person) WHERE (a)-[:knows]->(b) RETURN a.name AS a, b.name AS b ORDER BY b").to_list()
// #{"a": "marko", "b": "josh"}, #{"a": "marko", "b": "vadas"}
g.gql("MATCH (p:person) WHERE EXISTS (MATCH (p)-[:knows]->(f) MATCH (f)-[:created]->(:software {name: 'ripple'})) RETURN p.name AS name").to_list()   // #{"name": "marko"}

EXISTS stands anywhere an expression does: in WHERE and FILTER, in the inline WHERE of a node or edge pattern, under OR, XOR and CASE, in a RETURN or WITH column, an ORDER BY key, a grouping key or an aggregate's argument, a FOR list. It composes with three-valued logic like any boolean (Semantics).

g.gql("MATCH (p:person) WHERE p.age > 30 OR (p)<-[:knows]-() RETURN p.name AS name ORDER BY name").to_list()   // josh, peter, vadas
g.gql("MATCH (p:person) RETURN p.name AS name, EXISTS { (p)-[:knows]->() } AS knows ORDER BY knows DESC, name").to_list()
// #{"knows": true, "name": "marko"}, #{"knows": false, "name": "josh"}, ... peter, vadas
g.gql("MATCH (p:person) RETURN EXISTS { (p)-[:created]->() } AS creator, count(*) AS n ORDER BY creator").to_list()
// #{"creator": false, "n": 1}, #{"creator": true, "n": 3}
g.gql("MATCH (p:person WHERE NOT (p)-[:created]->())-[:knows]-(f) RETURN p.name AS p, f.name AS f").to_list()   // #{"f": "marko", "p": "vadas"}

The body holds MATCH clauses with their WHERE (and nested subqueries), or a whole query: any clauses (OPTIONAL MATCH, WITH, LET, FILTER, FOR, CALL), UNION and NEXT, ending in RETURN. EXISTS is then TRUE when that query returns at least one row, and its RETURN items are still evaluated (a failing expression there fails the query). Whole-query bodies nest at most 16 levels, CALL bodies included. A query holds at most 64 subqueries, pattern comprehensions, COUNT { } and COLLECT { } included (Errors).

g.gql("MATCH (p:person) WHERE EXISTS { MATCH (p)-[:created]->(s) WITH count(s) AS c WHERE c > 1 RETURN c } RETURN p.name AS name").to_list()   // #{"name": "josh"}
g.gql("MATCH (p:person) WHERE EXISTS { MATCH (p)-[:created]->(s) RETURN s UNION MATCH (p)-[:knows]->(s) RETURN s } RETURN p.name AS name ORDER BY name").to_list()   // josh, marko, peter
g.gql("MATCH (p:person) WHERE (p)-[:knows]->(q) RETURN p.name AS name")   // error: the pattern predicate introduces the new variable `q`
g.gql("MATCH (p:person) RETURN p.name AS name, (p)-[:knows]->() AS k")   // error: a pattern alone is a condition only in WHERE (42001)
g.gql("MATCH (p:person) WHERE EXISTS { MATCH (p)-[:created]->(s) } RETURN s.name AS s")   // error: `s` is bound inside a subquery

COUNT and COLLECT

COUNT { } counts and COLLECT { } collects what a subquery finds for each row. They are not GQL: like the list predicates they are openCypher compatibility forms, accepted with their Neo4j Cypher 25 meaning (Cypher Aliases). Their bodies are those of EXISTS, and they stand anywhere an expression does:

COUNT { <pattern> [WHERE <condition>] }       -- the number of matches
COUNT { MATCH ... }                           -- the same
COUNT { <query ending in RETURN> }            -- the number of rows the query returns
COLLECT { <query ending in RETURN <one item>> }   -- the list of that item, one entry per row

COUNT { } is an integer, 0 when nothing matches, never NULL; COUNT { .. } > 0 keeps the rows EXISTS keeps. COLLECT { } is a list in the order the body returns its rows (its own ORDER BY decides it), [] when there are none, with NULL items kept. Each row runs the body once, like the Gremlin twins project(..).by(__.out("created").count()) and by(__.out("created").values("name").fold()):

g.gql("MATCH (p:person) RETURN p.name AS name, COUNT { (p)-[:created]->() } AS n ORDER BY name").to_list()   // josh 2, marko 1, peter 1, vadas 0
g.v().has_label("person").order().by("name").project("name", "n").by("name").by(__.out("created").count()).to_list()   // the same rows
g.gql("MATCH (p:person) RETURN p.name AS name, COLLECT { MATCH (p)-[:created]->(s) RETURN s.name ORDER BY s.name } AS sw ORDER BY name").to_list()
// josh [lop, ripple], marko [lop], peter [lop], vadas []
g.gql("MATCH (p:person {name: 'marko'}) RETURN COLLECT { MATCH (p)-[:knows]->(f) RETURN f.lang } AS l").to_list()   // #{"l": [(), ()]}: NULLs kept
g.gql("MATCH (p:person) WHERE COUNT { (p)-[:created]->() } > 1 RETURN p.name AS name").to_list()   // #{"name": "josh"}
g.gql("MATCH (p:person) RETURN p.name AS name, COUNT { MATCH (p)-[:created]->(s) RETURN s.lang AS l UNION MATCH (p)-[:knows]->(f) RETURN f.name AS l } AS n ORDER BY name").to_list()
// josh 1 (java once), marko 3, peter 1, vadas 0

COLLECT { } needs a body ending in a RETURN of exactly one item. When a COUNT { } body is one query whose final RETURN only projects (no aggregate, DISTINCT, ORDER BY or UNION), its rows are counted without evaluating the RETURN items, so an expression there that would fail raises no error (Semantics).

g.gql("MATCH (p:person) RETURN COLLECT { MATCH (p)-[:knows]->(f) RETURN f.name, f.age } AS l")   // error: COLLECT { } needs a body that ends in a RETURN of exactly one column
g.gql("MATCH (p:person) RETURN p.name AS name, COUNT { MATCH (p)-[:created]->(s) RETURN 1 / 0 AS x } AS n ORDER BY name").to_list()   // josh 2, marko 1, peter 1, vadas 0: 1 / 0 never runs

OPTIONAL MATCH

OPTIONAL MATCH keeps every row that reaches it: where its pattern (and its own WHERE) matches, the row is extended once per match; where it does not, the row continues once with the new variables set to NULL. Gremlin's twin is optional().

g.gql("MATCH (p:person) OPTIONAL MATCH (p)-[:created]->(s) RETURN p.name AS name, s.name AS sw ORDER BY name, sw").to_list()
// #{"name": "josh", "sw": "lop"}, #{"name": "josh", "sw": "ripple"}, #{"name": "marko", "sw": "lop"}, #{"name": "peter", "sw": "lop"}, #{"name": "vadas", "sw": ()}
g.v().has_label("person").as("p").optional(__.out("created").as("s")).project("name", "sw").by(__.select("p").values("name")).by(__.coalesce(__.select("s").values("name"), __.constant("-"))).order().by("name").to_list()
// the same five rows, vadas with "-"

The WHERE of an OPTIONAL MATCH belongs to it: a row whose optional part fails the condition keeps its NULLs instead of being dropped. A leading OPTIONAL MATCH starts from one empty row, so a pattern without a match gives one row of NULLs:

g.gql("MATCH (p:person) OPTIONAL MATCH (p)-[:created]->(s) WHERE s.lang = 'none' RETURN p.name AS name, s AS s ORDER BY name").to_list()
// josh, marko, peter, vadas, each with s ()
g.gql("OPTIONAL MATCH (n:robot) RETURN n").to_list()   // #{"n": ()}

NULL columns then work as everywhere: count(s) skips them, so this counts each person's software, 0 for vadas (Aggregation).

LET and FILTER

LET name = expr names a value computed from the variables in scope; FILTER condition (FILTER WHERE condition too) keeps the rows for which it is TRUE, like a WHERE that may stand anywhere between the clauses. Neither changes the rows otherwise: MATCH ... LET ... FILTER ... runs exactly like the same query with the value written out in WHERE and RETURN, including the conditions that become has() (Plans and Performance).

g.gql("MATCH (p:person) LET decade = p.age / 10 * 10 FILTER decade = 30 RETURN p.name AS name, decade ORDER BY name").to_list()
// #{"decade": 30, "name": "josh"}, #{"decade": 30, "name": "peter"}
g.v().has_label("person").has("age", P.between(30, 40)).project("name", "decade").by("name").by(__.constant(30)).order().by("name").to_list()
// the same rows

A LET name may not be bound again, and a LET item may not read a name defined in the same LET (write a second LET).

WITH

WITH (Cypher; GQL's linear statements express the same) ends one part of the query and passes only its items on: the next clauses see only the names WITH lists (WITH * keeps all; with nothing in scope it passes the rows on, as in MATCH () CREATE () WITH * CREATE ()). An item that is not a plain variable needs AS. WITH may take DISTINCT, an aggregate, ORDER BY, OFFSET / SKIP, LIMIT and a WHERE, in this order; the WHERE filters after LIMIT (Cypher's order of the sub-clauses). The WHERE reads the items and also the variables the WITH drops (WITH c WHERE r IS NULL), except after an aggregation; after DISTINCT it filters the rows before they are folded (with DISTINCT and ORDER BY / OFFSET / LIMIT too, such a WHERE is not yet supported).

g.gql("MATCH (p:person) WITH p.name AS name, p.age AS age WHERE age < 30 RETURN name ORDER BY name").to_list()   // #{"name": "marko"}, #{"name": "vadas"}
g.gql("MATCH (p:person) WITH p ORDER BY p.age DESC LIMIT 2 MATCH (p)-[:created]->(s) RETURN p.name AS name, s.name AS sw ORDER BY name, sw").to_list()
// #{"name": "josh", "sw": "lop"}, #{"name": "josh", "sw": "ripple"}, #{"name": "peter", "sw": "lop"}
g.gql("MATCH (p:person) WITH p ORDER BY p.age LIMIT 3 WHERE p.age > 28 RETURN p.name AS name ORDER BY name").to_list()
// #{"name": "josh"}, #{"name": "marko"}: the three youngest, then the filter
g.gql("MATCH (p:person) OPTIONAL MATCH (p)-[e:created]->() WITH p.name AS name WHERE e IS NULL RETURN name").to_list()   // #{"name": "vadas"}
g.gql("MATCH (p:person) WITH p.name AS name RETURN p.age")   // error: the variable `p` is not in scope: the WITH before does not carry it
g.gql("MATCH (p:person) WITH p ORDER BY p.age LIMIT 2 WITH collect(p) AS ps WITH ps[0] AS youngest MATCH (youngest)<-[:knows]-(f) RETURN f.name AS name").to_list()   // #{"name": "marko"}
g.gql("MATCH (p:person) WITH collect(p.age) AS ages WITH ages[0] AS x MATCH (x)-->(y) RETURN y")   // error: `x` is written as a node of the pattern but holds a value that is not a node

A WITH that only renames and computes values is as transparent as LET. One with DISTINCT, an aggregate, ORDER BY, OFFSET or LIMIT builds its rows first; a later MATCH continues from the elements in its columns. A LET or WITH value computed from elements (coalesce(b, c), l[0], head(collect(e))) may stand for a node or an edge of a later pattern, also as an endpoint of INSERT / CREATE: NULL matches nothing, a value of another kind is a data error (22G03) when a row reaches the pattern (a value written as an edge is compared with the edges the pattern walks, so one of another kind matches nothing). A value written as a literal, an operator or a property access is never an element and is refused before the run. The order a WITH ... ORDER BY makes is not kept by later clauses: sort again in the final RETURN (Ordering).

FOR and UNWIND

FOR x IN list gives one row per item of the list, with the item bound to x; Cypher's UNWIND list AS x is the same clause (Cypher Aliases). The list is any expression over the row before the FOR: a literal, a $parameter, a property, a collect_list() column of a WITH, nodes(p). Duplicates and NULL items give rows like any other item; a list inside the list stays one item. WITH ORDINALITY i also binds the item's position from 1, WITH OFFSET i from 0 (only after FOR). Gremlin's twin is unfold().

g.gql("FOR x IN [1, 2, 2] RETURN x ORDER BY x").to_list()   // #{"x": 1}, #{"x": 2}, #{"x": 2}
g.inject([1, 2, 2]).unfold().order().to_list()   // 1, 2, 2
g.gql("UNWIND [1, 2, 2] AS x RETURN x ORDER BY x").to_list()   // the same rows
g.gql("FOR x IN [10, 20] WITH ORDINALITY i RETURN x, i ORDER BY i").to_list()   // #{"i": 1, "x": 10}, #{"i": 2, "x": 20}
g.gql("FOR x IN [10, 20] WITH OFFSET i RETURN x, i ORDER BY i").to_list()   // #{"i": 0, "x": 10}, #{"i": 1, "x": 20}
g.gql("FOR x IN [1, 2] FOR y IN [x, x * 10] RETURN x, y ORDER BY x, y").to_list()   // 1 1, 1 10, 2 2, 2 20

The most frequent use is "for each value in a list, find its vertex": an item compared in a property map or a WHERE equality. When an index or the element id serves that equality, each item is a direct lookup instead of a scan (Plans and Performance). A name without a vertex gives no row:

g.gql("FOR n IN $names WITH ORDINALITY i MATCH (p:person {name: n}) RETURN i, n, p.age AS age ORDER BY i", #{names: ["vadas", "marko", "nobody"]}).to_list()
// #{"age": 27, "i": 1, "n": "vadas"}, #{"age": 29, "i": 2, "n": "marko"}
g.gql("FOR id IN $ids MATCH (n) WHERE element_id(n) = id RETURN id, n.name AS name ORDER BY id", #{ids: ["1", "3", "42"]}).to_list()
// #{"id": "1", "name": "marko"}, #{"id": "3", "name": "lop"}

An item that is a vertex continues a pattern by its name, like a vertex column of a WITH (an item of another kind gives no row there):

g.gql("MATCH (p:person) WITH collect_list(p) AS ps FOR p IN ps MATCH (p)-[:created]->(s) RETURN p.name AS name, s.name AS sw ORDER BY name, sw").to_list()
// josh lop, josh ripple, marko lop, peter lop
g.gql("MATCH p = (a {name: 'marko'})-[:knows]->(b) FOR n IN nodes(p) MATCH (n)-[:created]->(s) RETURN DISTINCT n.name AS who, s.name AS sw ORDER BY who, sw").to_list()
// josh lop, josh ripple, marko lop

A NULL list gives no row and a value that is not a list gives one row of that value (Semantics). The item and the position are new names: a name already in scope, or the same name for both, is an error.

Queries without MATCH

A query may start with FOR, UNWIND, LET, WITH, FILTER or RETURN. It then starts from one empty row (Gremlin's inject(0)): RETURN alone returns one row, FILTER keeps or drops it, FOR turns it into one row per item, and a later MATCH runs once for each row.

g.gql("RETURN 1 + 2 AS three, upper('gql') AS up").to_list()   // #{"three": 3, "up": "GQL"}
g.gql("RETURN count(*) AS c").to_list()   // #{"c": 1}: the one empty row
g.gql("WITH 2 AS n RETURN n * n AS sq").to_list()   // #{"sq": 4}
g.gql("FILTER $on RETURN 1 AS x", #{on: false}).to_list()   // no row
g.gql("LET k = 30 MATCH (p:person) FILTER p.age > k RETURN p.name AS name ORDER BY name").to_list()   // #{"name": "josh"}, #{"name": "peter"}

RETURN

RETURN is mandatory in a query that only reads (a query whose last clause writes may end there, and FINISH ends any query without a result; Writing with GQL). It builds one map per row: RETURN expr AS name, ..., RETURN * (every named variable) and RETURN DISTINCT (duplicate rows removed, with GQL's equality: 1 and 1.0 are one value, Semantics). Result Shape covers names and column order.

g.gql("MATCH (a)-[:created]->(s) RETURN s.name AS s ORDER BY s").to_list()   // lop, lop, lop, ripple
g.gql("MATCH (a)-[:created]->(s) RETURN DISTINCT s.name AS s ORDER BY s").to_list()   // #{"s": "lop"}, #{"s": "ripple"}
g.v().out("created").values("name").dedup().order().to_list()   // "lop", "ripple"

Aggregation

RETURN and WITH items may aggregate. The items without an aggregate are the grouping keys: one row per distinct combination of their values (grouping is implicit, as in Cypher). Without keys the whole input is one group. ISO GQL's GROUP BY may follow the RETURN items: it must list exactly the items without an aggregate (by column name, or by repeating the item's expression), changes nothing in the result, and GROUP BY () is the single group of an all-aggregate RETURN; without any aggregate it gives one row per group, like DISTINCT. After WITH (Cypher) GROUP BY is an error that explains implicit grouping.

AggregateReturnsOn no input
count(*)the number of rows0
count(x)the number of rows where x is not NULL0
sum(x)the sum of the numbers; integers stay integers0
avg(x)the mean, always a floatNULL
min(x), max(x)the smallest / largest value in the order of ORDER BYNULL
collect_list(x) (Cypher collect(x))the values as a list[]
percentile_disc(x, p) (Cypher percentileDisc)the value at percentile p (0.0 to 1.0) of the sorted numbers, with its typeNULL
percentile_cont(x, p) (Cypher percentileCont)the percentile p interpolated linearly between the two nearest numbers, always a floatNULL

The percentiles take numbers (another kind is error 22G03) and a percentile p from 0.0 to 1.0 (outside it: error 22003), evaluated and checked on every row; the group uses the value of its first row, so write a constant or a $parameter. percentile_disc returns the value at position ceil(p * n) - 1 of the n sorted numbers (the first for p = 0), percentile_cont interpolates at position p * (n - 1) (Neo4j's definitions):

g.gql("MATCH (p:person) RETURN percentile_disc(p.age, 0.5) AS d, percentile_cont(p.age, 0.5) AS c, percentileCont(p.age, 1) AS top").to_list()   // #{"c": 30.5, "d": 29, "top": 35.0}
g.gql("MATCH (p:person) RETURN percentile_cont(p.age, 1.5) AS c")   // error: percentile_cont() takes a percentile from 0.0 to 1.0, not 1.5 (22003)

NULL values are skipped by every aggregate except count(*). DISTINCT inside the call (count(DISTINCT x)) aggregates each distinct value once. An aggregate may be part of an expression (count(*) + 1); outside its aggregates such an item reads only grouping keys, constants and parameters. It may repeat a key written as a variable or a property (p.age + count(*) beside the key p.age), not a computed key (a.age + b.age): compute that one in a WITH first, as in WITH *, a.age + b.age AS k RETURN k, k + count(*). The details are on Semantics.

g.gql("MATCH (p:person) RETURN count(*) AS n, sum(p.age) AS total, avg(p.age) AS mean, min(p.age) AS lo, max(p.age) AS hi").to_list()
// #{"hi": 35, "lo": 27, "mean": 30.75, "n": 4, "total": 123}
g.v().has_label("person").values("age").fold().project("n", "total", "mean", "lo", "hi").by(__.count(Scope.local)).by(__.sum(Scope.local)).by(__.mean(Scope.local)).by(__.min(Scope.local)).by(__.max(Scope.local)).to_list()
// the same values
g.gql("MATCH (s:software)<-[:created]-(p) RETURN s.name AS sw, count(p) AS authors ORDER BY sw").to_list()
// #{"authors": 3, "sw": "lop"}, #{"authors": 1, "sw": "ripple"}
g.v().has_label("software").group().by("name").by(__.in("created").count()).to_list()   // #{"lop": 3, "ripple": 1}
g.gql("MATCH (p:person)-[:created]->(s) RETURN p.name AS name, collect_list(s.name) AS sw ORDER BY name").to_list()
// #{"name": "josh", "sw": ["ripple", "lop"]}, #{"name": "marko", "sw": ["lop"]}, #{"name": "peter", "sw": ["lop"]}
g.gql("MATCH (n) RETURN count(n.age) AS ages, count(*) AS all, count(DISTINCT n.lang) AS langs").to_list()
// #{"ages": 4, "all": 6, "langs": 1}

With OPTIONAL MATCH, count() of an optional variable gives 0 where nothing matched; Gremlin counts per vertex with group() or project():

g.gql("MATCH (p:person) OPTIONAL MATCH (p)-[:created]->(s) RETURN p.name AS name, count(s) AS n ORDER BY name").to_list()
// josh 2, marko 1, peter 1, vadas 0
g.v().has_label("person").project("name", "n").by("name").by(__.out("created").count()).order().by("name").to_list()
// the same rows

An aggregating WITH passes the groups on, and its WHERE filters them (SQL's HAVING):

g.gql("MATCH (p:person)-[:created]->(s) WITH p, count(s) AS n WHERE n > 1 RETURN p.name AS name, n").to_list()   // #{"n": 2, "name": "josh"}
g.gql("MATCH (p:person)-[:created]->(s) RETURN p.name AS name, count(s) AS n GROUP BY name").to_list()   // the same rows as without GROUP BY
g.gql("MATCH (p:person) WITH p.name AS n, count(*) AS c GROUP BY n RETURN n, c")   // error: GROUP BY is not needed: grouping is implicit
g.gql("MATCH (p:person) WHERE count(p) > 1 RETURN p")   // error: an aggregate cannot be used in WHERE
g.gql("MATCH (p:person) RETURN sum(p.name) AS s")   // error: sum() takes numbers, not a string (22G03)

After an aggregation ORDER BY reads the returned columns only: by their names, or written again inside an expression, an aggregate call or a property access as an item has it (ORDER BY count(s) + 1, ORDER BY p.name + 'x' when p.name is a key). An expression written like another item next to an aggregate stays refused, as in Neo4j. The groups come out in an unspecified order: write ORDER BY.

g.gql("MATCH (p:person)-[:created]->(s) RETURN p.name AS name, count(s) AS n ORDER BY 10 - count(s), p.name").to_list()   // #{"n": 2, "name": "josh"}, #{"n": 1, "name": "marko"}, #{"n": 1, "name": "peter"}
g.gql("MATCH (p:person)-[:created]->(s) RETURN count(s) AS n ORDER BY p.age + count(s)")   // error: after an aggregation, ORDER BY can only use the returned columns

ORDER BY, OFFSET, LIMIT

ORDER BY takes expressions (a column name, a property, a function call) with ASC / ASCENDING (the default) or DESC / DESCENDING; it may read variables that are not returned (except after RETURN DISTINCT). OFFSET n (Cypher SKIP n) skips rows, LIMIT n keeps at most n. They come in this order, each at most once; n is a non-negative integer literal, a parameter, or a constant expression: one without variables, aggregates or subqueries, evaluated once before the run (LIMIT 1 + 1, SKIP toInteger(ceil(1.7)); a negative result is an error 22G02, a non-integer one 22G03). An expression with a parameter in it (LIMIT $n + 1) is refused: pass the computed value as the parameter.

g.gql("MATCH (n:person) RETURN n.name AS name ORDER BY n.age DESC").to_list()   // peter, josh, marko, vadas
g.gql("MATCH (n:person) RETURN n.name AS name ORDER BY name OFFSET 1 LIMIT 2").to_list()   // #{"name": "marko"}, #{"name": "peter"}
g.v().has_label("person").values("name").order().range(1, 3).to_list()   // "marko", "peter"
g.gql("MATCH (n:person) RETURN n.name AS name ORDER BY name OFFSET 2 - 1 LIMIT toInteger(ceil(1.7))").to_list()   // #{"name": "marko"}, #{"name": "peter"}
g.gql("MATCH (n:person) RETURN n.name AS name LIMIT n.age").to_list()   // error: LIMIT ... not an expression that reads the row (22G03)

Without ORDER BY the row order is unspecified; Semantics gives the order of NULL and of values of different types.

UNION and NEXT

UNION combines the rows of queries that each end in RETURN. Every operand returns the same column names, in any order; the result has the column order of the first operand. UNION (also written UNION DISTINCT) removes duplicate rows with GQL's equality (1 and 1.0 are one value), UNION ALL keeps them; one chain uses one kind. Each operand is a query of its own: its own variables, and its own ORDER BY, OFFSET and LIMIT, which apply to that operand only. Gremlin's twin is union(), followed by dedup() for UNION:

g.gql("MATCH (p:person) WHERE p.age > 30 RETURN p.name AS name UNION MATCH (s:software) RETURN s.name AS name").to_list()   // josh, peter, lop, ripple (in any order)
g.union(__.V().has("person", "age", P.gt(30)), __.V().has_label("software")).values("name").to_list()   // "josh", "peter", "lop", "ripple"
g.gql("MATCH (p:person) RETURN p.name AS name UNION ALL MATCH (p:person)-[:created]->() RETURN p.name AS name").count().next()   // 8: duplicates kept
g.gql("RETURN 1 AS a, 2 AS b UNION RETURN 2 AS b, 1 AS a").to_list()   // #{"a": 1, "b": 2}: one row, the first operand's order
g.gql("MATCH (p:person) RETURN p.name AS name ORDER BY p.age DESC LIMIT 1 UNION ALL MATCH (s:software) RETURN s.name AS name ORDER BY name LIMIT 1").to_list()   // peter, lop: per operand
g.gql("RETURN 1 AS x UNION RETURN 2 AS y")   // error: the operands of UNION must return the same column names
g.gql("RETURN 1 AS x UNION RETURN 2 AS x UNION ALL RETURN 3 AS x")   // error: UNION ALL is mixed with UNION in one query

NEXT continues after a RETURN: the rows that RETURN builds are the input of the next statement, which sees only its columns, by name (RETURN * passes every variable on). It may start with any clause: NEXT RETURN, NEXT FILTER, NEXT MATCH continuing from an element column. NEXT binds looser than UNION, so a NEXT after a union sorts, filters, pages or aggregates the whole union, which no operand's ORDER BY can:

g.gql("MATCH (p:person) RETURN p.name AS name UNION MATCH (s:software) RETURN s.name AS name NEXT RETURN name ORDER BY name LIMIT 3").to_list()   // josh, lop, marko
g.gql("MATCH (p:person) RETURN p.name AS name, p.age AS age NEXT FILTER age > 30 RETURN name ORDER BY name").to_list()   // #{"name": "josh"}, #{"name": "peter"}
g.gql("MATCH (p:person) RETURN p NEXT MATCH (p)-[:created]->(s) RETURN p.name AS who, s.name AS sw ORDER BY who, sw").to_list()   // josh lop, josh ripple, marko lop, peter lop
g.gql("MATCH (p:person) RETURN p.name AS name, p.age AS age NEXT RETURN count(*) AS n, avg(age) AS mean").to_list()   // #{"mean": 30.75, "n": 4}
g.gql("MATCH (p:person) RETURN p.name AS name NEXT RETURN p.age")   // error: the variable `p` is not in scope: the RETURN before NEXT does not return it

A NEXT after a plain query is the Cypher WITH of the same items: q1 RETURN a, b NEXT q2 gives the rows of q1 WITH a, b q2 (Cypher Aliases). NEXT YIELD is not supported yet.

CALL subqueries

CALL { } runs a whole query (any clauses, UNION, NEXT, ending in RETURN) once for each incoming row, and joins the row with each row the body returns: the columns of the body's RETURN become new variables of the query. Three things make it more than a MATCH:

  • the body's aggregates, DISTINCT, ORDER BY and LIMIT apply to each row's records: a count per row, the top k per group;
  • a row whose body returns no row is dropped, OPTIONAL CALL keeps it with the new variables NULL (an aggregating body returns one row anyway: count is 0 there);
  • a UNION or NEXT inside the body works per row too.
CALL (a, b) { <query> }       -- imports a and b (GQL and Cypher 25)
CALL (*) { <query> }          -- imports every variable in scope
CALL () { <query> }           -- imports nothing
CALL { <query> }              -- imports nothing, unless it starts with WITH a, b (Cypher's importing WITH)
OPTIONAL CALL ...             -- keeps a row without results, with NULL columns

g.gql("MATCH (p:person) CALL (p) { MATCH (p)-[e:created]->(s) RETURN s.name AS top ORDER BY e.weight DESC LIMIT 1 } RETURN p.name AS who, top ORDER BY who").to_list()
// #{"top": "ripple", "who": "josh"}, #{"top": "lop", "who": "marko"}, #{"top": "lop", "who": "peter"}: vadas has no row
g.v().has_label("person").as("p").flat_map(__.out_e("created").order().by("weight", Order.desc).limit(1).in_v()).project("who", "top").by(__.select("p").values("name")).by("name").to_list()   // the same three rows
g.gql("MATCH (p:person) OPTIONAL CALL (p) { MATCH (p)-[:created]->(s) RETURN s.name AS sw ORDER BY sw LIMIT 1 } RETURN p.name AS who, sw ORDER BY who").to_list()
// josh lop, marko lop, peter lop, vadas ()
g.gql("MATCH (p:person) CALL (p) { MATCH (p)-[:knows]->(f) RETURN count(f) AS friends } RETURN p.name AS who, friends ORDER BY who").to_list()   // josh 0, marko 2, peter 0, vadas 0
g.gql("MATCH (p:person) CALL (p) { MATCH (p)-[:knows]->(f) RETURN f.name AS other UNION MATCH (p)-[:created]->(s) RETURN s.name AS other } RETURN p.name AS who, other ORDER BY who, other").to_list()
// josh lop, josh ripple, marko josh, marko lop, marko vadas, peter lop
g.gql("MATCH (p:person) CALL { WITH p MATCH (p)-[:created]->(s) RETURN s.name AS sw } RETURN p.name AS who, sw ORDER BY who, sw").to_list()   // Cypher's importing WITH: josh lop, josh ripple, marko lop, peter lop

The body reads only the variables it imports: in CALL { MATCH (p)-->(s) .. } without a scope clause, p is a new variable of the body, not the outer one. A body that imports nothing still runs once per row (Semantics). The returned names must be new, and a body without RETURN (a unit subquery) must end in a write (Inside CALL): a body that only reads must return something; IN TRANSACTIONS is refused. A later clause continues from a returned element as from a WITH column:

g.gql("CALL { MATCH (s:software) RETURN s } MATCH (s)<-[:created]-(p) RETURN s.name AS sw, count(p) AS n ORDER BY sw").to_list()   // lop 3, ripple 1
g.gql("MATCH (p:person) CALL (p) { MATCH (p)-[:knows]->(f) RETURN f AS p } RETURN p")   // error: the CALL body returns `p`, which is already defined outside it
g.gql("MATCH (p:person) CALL (p) { MATCH (p)-[:created]->(s) } RETURN p")   // error: a CALL { } body without RETURN only makes sense for writes

Calling saved queries

CALL folder.name(args) is GQL's named procedure call: it runs the saved query name of the catalog folder folder (the segments before the name joined by /; one segment, CALL name(), calls a query of the root folder) for each incoming row, like a CALL { } body that imports nothing. Only saved queries written in GQL can be called.

CALL f.name(a, b) YIELD x, y AS z [WHERE <condition>]   -- inside a query: YIELD names the columns read after it
CALL f.name(a, b)                -- inside a query, a VOID saved query (no RETURN): each row kept once
MATCH .. CALL f.name(a, b)       -- a VOID call may end the query, like a write: zero rows
CALL f.name() YIELD n MATCH (n)-->(m) ..   -- a yielded node (or edge) starts a later pattern
OPTIONAL CALL f.name(a) YIELD x  -- keeps a row without results, with x NULL
CALL f.name(a, b)                -- the whole query: every column of the saved query
CALL f.name(a, b) YIELD *        -- the same
CALL f.name                      -- the whole query, arguments from the query's parameters by name
  • The arguments are constants or $parameters (and lists, maps and arithmetic of them), positional in the order the saved query first reads its parameters; trailing ones left out take their defaults, and each is checked against the parameter's schema before the run. An argument that reads the row is not supported yet.
  • YIELD names columns of the saved query's RETURN; each yielded name is a new variable (AS renames one, also swapping two names), and WHERE after the items filters the rows. Inside a query, a call of a saved query with columns needs YIELD; YIELD * and the form without parentheses are for a standalone call only.
  • The saved query runs as a query of its own: it sees none of the caller's variables, and its variables none of the caller's. Its writes are part of the calling query's one unit.
  • A call stands wherever a clause stands, also inside CALL { } bodies and UNION operands; inside EXISTS { }, COUNT { } and COLLECT { } it is not supported yet. The vendor namespaces db, dbms, apoc and gds are refused.
g.define_query(#{
    name: "older",
    folder: "people",
    language: "gql",
    params: #{min: #{schema: #{type: "integer"}, default: 30}},
    body: "MATCH (p:person) WHERE p.age > $min RETURN p.name AS name, p.age AS age"
});
g.gql("MATCH (s:software) CALL people.older(33) YIELD name RETURN s.name AS sw, name ORDER BY sw").to_list();
// [#{"name": "peter", "sw": "lop"}, #{"name": "peter", "sw": "ripple"}]
g.gql("MATCH (s:software) OPTIONAL CALL people.older(40) YIELD name RETURN s.name AS sw, name ORDER BY sw").to_list();
// [#{"name": (), "sw": "lop"}, #{"name": (), "sw": "ripple"}]
g.gql("CALL people.older(26) YIELD name RETURN name UNION CALL people.older(33) YIELD name RETURN name").to_list();
// marko, vadas, josh, peter
g.gql("CALL people.older").to_list();   // [#{"age": 32, "name": "josh"}, #{"age": 35, "name": "peter"}]: min takes its default 30

.profile() shows a call as gql:call_query("people/older", ..) with the saved query's plan as its child. Saved Queries has the parameters, VOID queries, effects and permissions; Errors every error of a call.

INSERT

INSERT <pattern>, ... (Cypher CREATE) creates the pattern's new nodes and edges once for each row that reaches it; a variable bound before connects an existing node. Edges need a direction and one label, node labels are a conjunction (:A&B, Cypher :A:B). The full rules are on Writing with GQL.

g.gql("MATCH (p:person {name: 'marko'}) INSERT (p)-[:likes]->(f:fruit {name: 'apple'}) RETURN f.name AS fruit").to_list()   // #{"fruit": "apple"}
g.gql("FOR n IN ['ann', 'bob'] CREATE (:person {name: n})").to_list()   // no rows

SET and REMOVE

SET <item>, ... changes the elements of each row that reaches it, items left to right: a property (SET n.k = expr), all properties (SET n = {..}; Cypher's merge SET n += {..}) or labels of a node (SET n:A, SET n IS A). REMOVE <item>, ... removes a property (REMOVE n.k) or labels (REMOVE n:A). A NULL value removes the property, a NULL target is skipped. The full rules are on Writing with GQL.

g.gql("MATCH (p:person {name: 'marko'}) SET p.age = p.age + 1, p:admin RETURN p.age AS age, labels(p) AS labels").to_list()   // #{"age": 30, "labels": ["person", "admin"]}
g.gql("MATCH (p:person {name: 'marko'}) REMOVE p.age RETURN keys(p) AS keys").to_list()   // #{"keys": ["name"]}

DELETE

[DETACH | NODETACH] DELETE <expr>, ... removes the nodes, edges, paths and lists of them its expressions give, for each row. DETACH DELETE removes a node with its edges; a plain DELETE (the default, also written NODETACH DELETE) fails the query (G1001) for a node that still has edges the same clause does not delete. A NULL target is skipped; reading or returning a deleted element later in the query is an error. The full rules are on Writing with GQL.

g.gql("MATCH (p:person {name: 'vadas'}) WITH p, p.name AS name DETACH DELETE p RETURN name").to_list()   // #{"name": "vadas"}
g.gql("MATCH (a {name: 'marko'})-[e:knows]->() DELETE e RETURN count(e) AS deleted").to_list()   // #{"deleted": 2}

MERGE

MERGE [p =] <pattern> [ON CREATE SET <items>] [ON MATCH SET <items>] (Cypher, a compatibility form) looks for its one pattern on each row: every match is a row, and when nothing matches, the whole pattern is created, reusing the nodes bound before. Each row sees what the rows before it created. ON CREATE SET and ON MATCH SET hold SET items for the created or the found elements. A NULL property value in the pattern fails the query (22004). The full rules are on Writing with GQL.

g.gql("FOR n IN ['ann', 'ann'] MERGE (p:person {name: n}) ON CREATE SET p.new = true RETURN count(DISTINCT p) AS people").to_list()   // #{"people": 1}
g.gql("MATCH (a:person {name: 'marko'}), (b:person {name: 'josh'}) MERGE (a)-[e:knows]->(b) RETURN e.weight AS weight").to_list()   // #{"weight": 1.0}: found

// #{"m": #{"age": 32, "name": "josh"}}

RECORD {k: v} is the ISO record constructor with its keyword written out; it builds the same map as {k: v}. The word is contextual, not reserved: RECORD (any case) followed by { and then } or name: is the constructor; anywhere else record is an ordinary variable, also before a map projection such as record {.name}. A variable named record whose projection is empty or starts with a key: expr item is back-quoted: `record` {k: 1}.

Integer arithmetic stays integer (/ truncates toward zero, % takes the sign of the dividend); a float operand makes the result a float. An overflow or an integer division by zero is an error, never a wrapped value (Errors); a float divided by zero follows IEEE 754 (1.0 / 0.0 is Infinity, 0.0 / 0.0 is NaN; Semantics).

g.gql("RETURN [1, 2] + 3 AS a, 0 + [1] AS b, [1] + [2] AS c").to_list()   // #{"a": [1, 2, 3], "b": [0, 1], "c": [1, 2]}

Indexing and slicing

x[i] reads the item i of a list, counted from 0; a negative index counts from the end (x[-1] is the last item), and an index out of range gives NULL. x[a..b] is the sub-list from a up to b (excluded); either bound may be left out (x[..2], x[1..]), a negative one counts from the end, bounds beyond the list are clamped, and a >= b gives []. On a map m[k] reads the entry of the string key k, and on a node or an edge n[k] reads the property k; a missing key gives NULL. n['name'] with a string literal is the property access n.name (the same plan, so a property index serves it); a computed key (n[$key], n['na' || 'me']) is read per row. A NULL list, map, index or bound gives NULL. These are Cypher forms with their Neo4j meaning, measured against the openCypher TCK (Semantics).

g.gql("RETURN [10, 20, 30][0] AS a, [10, 20, 30][-1] AS b, [10, 20, 30][5] AS c, [10, 20, 30][1..] AS d, [10, 20, 30][..-1] AS e").to_list()
// #{"a": 10, "b": 30, "c": (), "d": [20, 30], "e": [10, 20]}
g.gql("MATCH (p:person) WITH p ORDER BY p.age RETURN collect(p.name)[0] AS youngest, collect(p.name)[-2..] AS oldest").to_list()
// #{"oldest": ["josh", "peter"], "youngest": "vadas"}
g.gql("MATCH (p:person {name: 'marko'}) RETURN p['na' || 'me'] AS name, {lang: 'java'}['lang'] AS lang").to_list()
// #{"lang": "java", "name": "marko"}
g.gql("MATCH (p:person {name: 'josh'}) RETURN p[$key] AS v", #{key: "age"}).to_list()   // #{"v": 32}
g.gql("RETURN 'abc'[0] AS c")   // error: cannot index a string

The index of a list is an integer (x[1.0] and x['1'] are errors, GQLSTATUS 22G03; convert with toInteger(i)), the key of a map or an element a string; a text is no list (use substring(s, start, length)). These errors arise when a row reaches the expression, as for every other operand of the wrong kind (Errors).

Map projections and comprehensions

Three Cypher forms build maps and lists inside an expression. They are not GQL; gql() accepts them with their Neo4j meaning because Cypher users and LLMs write them all the time (Cypher Aliases). Together they give a JSON-shaped answer: one row per entity, its related data nested inside.

v {.key, .*, x, key: expr}                    -- map projection of a vertex, an edge or a map
[x IN list]  [x IN list WHERE cond]  [x IN list | expr]  [x IN list WHERE cond | expr]
[(a)-[:R]->(b) WHERE cond | expr]             -- pattern comprehension, also [p = (a)-->(b) | p]

Map projection. v {...} builds a map from the variable v: .key is its property (NULL when missing, the key kept), .* every stored property (no id, no labels), x the entry x: x, and key: expr any value, all in the written order. Its Gremlin twins are project() and value_map().by(unfold()); the GQL form is the record constructor {name: p.name}, which differs only for a NULL variable (Semantics):

g.gql("MATCH (p:person) RETURN p {.name, .age, decade: p.age / 10} AS m ORDER BY p.name LIMIT 2").to_list()
// #{"m": #{"age": 32, "decade": 3, "name": "josh"}}, #{"m": #{"age": 29, "decade": 2, "name": "marko"}}
g.gql("MATCH (p:person {name: 'marko'}) RETURN p {.*} AS m").to_list()   // #{"m": #{"age": 29, "name": "marko"}}
g.v().has("name", "marko").value_map().by(__.unfold()).to_list()   // #{"age": 29, "name": "marko"}
g.gql("MATCH (p:person {name: 'marko'})-[e:knows]->(f) RETURN e {.*, to: f.name} AS k ORDER BY k.to").to_list()
// #{"k": #{"to": "josh", "weight": 1.0}}, #{"k": #{"to": "vadas", "weight": 0.5}}

List comprehension. [x IN list WHERE cond | expr] walks the list in its order, keeps the items for which cond is TRUE and maps each kept item to expr; leave out WHERE to keep every item, | expr to keep the item itself. x is a new name that exists only inside the brackets. The Gremlin twin is local(__.unfold().is(..).fold()):

g.gql("RETURN [x IN range(1, 5) WHERE x % 2 = 1] AS odd, [x IN range(1, 3) | x * x] AS sq, [x IN [1, 2] | [y IN [10, 20] | x * y]] AS grid").to_list()
// #{"grid": [[10, 20], [20, 40]], "odd": [1, 3, 5], "sq": [1, 4, 9]}
g.inject([1, 2, 3, 4, 5]).local(__.unfold().is(P.gt(2)).fold()).to_list()   // [3, 4, 5]
g.gql("MATCH p = (a {name: 'marko'})-[:knows|created]->{2}(b) RETURN [x IN nodes(p) | x.name] AS names ORDER BY b.name").to_list()
// #{"names": ["marko", "josh", "lop"]}, #{"names": ["marko", "josh", "ripple"]}
g.gql("MATCH (p:person) RETURN p.name AS name, [x IN [p.age, p.age + 10] WHERE x > 30] AS l ORDER BY name LIMIT 2").to_list()
// #{"l": [32, 42], "name": "josh"}, #{"l": [39], "name": "marko"}

A | inside the list or the WHERE part ends that part, so a label alternative there needs parentheses: [x IN l WHERE x:(A|B) | x.name].

Pattern comprehension. [(a)-[:R]->(b) WHERE cond | expr] is the list of expr for every match of the pattern on the row: [] when nothing matches, never NULL. The pattern has at least one edge; it reads the variables bound before it (they are imported, like in EXISTS), and the names it binds itself (b here, or a path variable p = ...) exist only inside the brackets. It is a subquery: the Gremlin twin is project(..).by(__.out("knows").values("name").fold()), and the items come in no defined order.

g.gql("MATCH (p:person {name: 'marko'}) RETURN [(p)-[:knows]->(f) | f.name] AS friends").to_list()   // #{"friends": ["josh", "vadas"]}, in any order
g.v().has("name", "marko").project("friends").by(__.out("knows").values("name").fold()).to_list()   // #{"friends": ["josh", "vadas"]}
g.gql("MATCH (s:software {name: 'ripple'}) RETURN [(s)<-[:created]-(p) WHERE p.age > 30 | p.name] AS older").to_list()   // #{"older": ["josh"]}
g.gql("MATCH (p:person) WHERE size([(p)-[:created]->(s) | s]) >= 2 RETURN p.name AS name").to_list()   // #{"name": "josh"}
g.gql("MATCH (p:person {name: 'marko'}) RETURN [q = (p)-[:knows]->() | path_length(q)] AS l").to_list()   // #{"l": [1, 1]}

Together, one row per person with its friends and projects nested inside, the shape a JSON API or an LLM wants (Result Shape):

g.gql("MATCH (p:person) RETURN p {.name, friends: [(p)-[:knows]->(f) | f.name], projects: [(p)-[:created]->(s) | s {.name, .lang}]} AS person ORDER BY person.name").to_json()
// [{"person": {"name": "josh", "friends": [], "projects": [{"name": "ripple", "lang": "java"}, ...]}}, ...]

All three stand anywhere an expression does (WHERE, RETURN, WITH, LET, FILTER, FOR, ORDER BY, an aggregate's argument) and nest in each other. Their rules:

  • A comprehension variable must be a new name: one that is in scope, or that the query uses anywhere else, is an error (Semantics).
  • No aggregate inside the WHERE or | part (aggregate in a WITH first, or aggregate the list: size([..])).
  • A list-comprehension variable cannot be read inside an EXISTS or a pattern comprehension in its WHERE or | part yet (Not supported yet).
  • A pattern comprehension counts as a subquery: a query holds at most 64 subqueries (Errors).
  • The list predicates all(), any(), none(), single() and reduce() follow the same rules for their variables (below).
g.gql("MATCH (p:person) RETURN [p IN [1, 2] | p * 2] AS l")   // error: the comprehension variable `p` shadows the variable `p` in scope
g.gql("MATCH (p:person) RETURN [(p)-[:knows]->(f) | count(f)] AS l")   // error: count() cannot be used inside the | part of a pattern comprehension
g.gql("MATCH (p:person) RETURN p.name AS n, [(p)-[:knows]->(f) | f.name] AS l ORDER BY f.name")   // error: `f` is bound inside a pattern comprehension
g.gql("RETURN size([x IN [1, 2, 3] WHERE x > 0]) = size([1, 2, 3]) AS all_positive").to_list()   // #{"all_positive": true}

List predicates and reduce

Cypher's all(x IN l WHERE c), any(..), none(..), single(..) and reduce(acc = init, x IN l | expr) are openCypher compatibility forms (Cypher Aliases has their NULL rules). The predicates are three-valued: a NULL list or, when no item decides the answer, a NULL condition gives NULL. A list comprehension counted with size() gives the same answer when no condition is NULL; over a pattern comprehension they are the Gremlin where(__..) / not(__..) of a pattern. reduce folds a list per row, where FOR and an aggregate fold the rows of a query.

g.gql("RETURN all(x IN [1, 2, 3] WHERE x > 0) AS a, any(x IN [1, NULL] WHERE x > 1) AS b, single(x IN [1, 2] WHERE x > 1) AS c").to_list()   // #{"a": true, "b": (), "c": true}
g.gql("RETURN size([x IN [1, 2, 3] WHERE x > 0]) = size([1, 2, 3]) AS a").to_list()   // #{"a": true}, the count form of all()
g.gql("MATCH (p:person) WHERE all(w IN [(p)-[:created]->(s) | s] WHERE w.lang = 'java') AND any(a IN [(p)-[:knows]->(f) | f.age] WHERE a > 30) RETURN p.name AS name").to_list()   // #{"name": "marko"}
g.V().hasLabel("person").not(__.out("created").has("lang", P.neq("java"))).where(__.out("knows").has("age", P.gt(30))).values("name").to_list()   // "marko"
g.gql("MATCH (p:person) RETURN p.name AS name, reduce(s = 0, a IN [(p)-[:knows]->(f) | f.age] | s + a) AS ages ORDER BY name").to_list()   // josh 0, marko 59, peter 0, vadas 0
g.gql("FOR x IN [1, 2, 3] RETURN sum(x) AS s").to_list()   // #{"s": 6}, one fold over the rows
g.gql("RETURN reduce(s = 0, x IN [1, 2, 3] | s + x) AS s").to_list()   // #{"s": 6}, one fold per row
g.gql("MATCH (p:person) RETURN all(p IN [1] WHERE p > 0) AS a")   // error: the variable `p` of all() shadows the variable `p` in scope
g.gql("MATCH (p:person) RETURN any(x IN [1] WHERE x > count(*)) AS a")   // error: count() cannot be used inside the WHERE part of all(), any(), none() or single()

Functions

Function names are case-insensitive (toInteger, TOINTEGER). Every function returns NULL for a NULL argument (except coalesce, nullif and the ...OrNull conversions, by their definition) and fails for an argument of the wrong kind (22G03), never with a silent NULL. A position or a length counts characters (Unicode scalar values), never bytes. The aggregates are listed under Aggregation; Semantics has the exact rules and where they differ from Neo4j and from the Gremlin steps of the same name.

The functions come from two sources: the GQL functions (with their Cypher spellings as aliases), and a fixed list of openCypher compatibility functions that GQL has no counterpart for (toInteger, substring, split, round, keys, nodes, ...): they keep their Neo4j meaning (Cypher Aliases).

Dates and times

The temporal values are the engine's six date and time types (date, time, offsettime, localdatetime, datetime, duration): a value gql() builds is the same value a Gremlin step or a stored property holds, and a stored date reads as a date (n.born.year). The functions are openCypher's (Neo4j Cypher 25) with Neo4j's meaning; the constructors also have their ISO GQL names. The places where an answer differs from Neo4j are on Semantics, and the Gremlin step that does the same as each function on Dates in GQL.

The map form does the same as in Neo4j: datetime({epochSeconds: s}) with an optional millisecond / microsecond / nanosecond, or datetime({epochMillis: ms}), each with an optional timezone (the instant shown in that zone); no other field may stand next to them.

g.gql("RETURN datetime.fromepoch(1416779, 999999000) AS a, datetime.fromepochmillis(237821673987) AS b").to_list()
// #{"a": datetime("1970-01-17T09:32:59.999999Z"), "b": datetime("1977-07-15T13:34:33.987Z")}
g.gql("RETURN datetime({epochSeconds: 1416779, microsecond: 5}) AS a, datetime({epochMillis: 237821673987, timezone: '+01:00'}) AS b").to_list()
// #{"a": datetime("1970-01-17T09:32:59.000005Z"), "b": datetime("1977-07-15T14:34:33.987+01:00")}

g.gql("RETURN date('2017-10-11').year AS y, date('2017-10-11').week AS w, date('2017-10-11').dayOfWeek AS dw, date('1984-01-01').weekYear AS wy, date('1984-10-11').ordinalDay AS o").to_list()

Arithmetic and comparison

FormResult
x + dur, dur + x, x - dur (x a date, localtime, time, localdatetime or datetime)a value of x's type: the duration's months (the day clamped to the month's end), then its days, then its time part, each where the type has it
dur + dur, dur - durpart by part (P1D + PT49H is P1DT49H)

A date takes the months, the days and the whole days of the time part (toward zero: PT33H adds one day, PT-33H takes one away), a localtime and a time only the time part, wrapping around midnight (a time keeps its offset). A datetime keeps its offset, or, with a zone name, follows its zone: a day added across a daylight saving change keeps the wall-clock time. Two values that are not both durations cannot be added (22G03: the time between them is duration.between(a, b)); dur / 0 is 22012; a result outside the years -9999 to 9999 is 22008.

g.gql("RETURN date('2024-01-31') + duration('P1M') AS a, date('1997-09-11') + duration('P29DT33H') AS b, localtime('23:00') + duration('PT2H') AS c, localdatetime('2015-07-21T21:40') - duration('PT1H30M') AS d").to_list()
// #{"a": date("2024-02-29"), "b": date("1997-10-11"), "c": time("01:00:00"), "d": localdatetime("2015-07-21T20:10:00")}
g.gql("RETURN duration('P1M') * 0.5 AS a, duration('P1Y') / 2 AS b, duration('P1D') + duration('PT49H') AS c, -duration('P1D') AS d").to_list()
// #{"a": duration("P15DT5H14M33S"), "b": duration("P6M"), "c": duration("P1DT49H"), "d": duration("-P1D")}
g.gql("RETURN date('2015-01-01') + date('2015-01-01') AS x")   // fails: + adds a duration to a temporal value (22G03)

Values of one type compare by calendar and clock, two datetimes by their instant (12:00+01:00 = 11:00Z is TRUE). Two durations are equal when their months, days and time part are, but they are not ordered: <, >, <=, >= on two durations are NULL (a month has no fixed length); ORDER BY still sorts them, by their length with a month of 30 days. Values of different temporal types are never equal (= FALSE) and not ordered (NULL), as values of different kinds are (Comparisons across types).

g.gql("RETURN datetime('2015-07-21T12:00+01:00') = datetime('2015-07-21T11:00Z') AS a, date('2015-01-01') < date('2016-01-01') AS b, duration('P1M') < duration('P30DT1S') AS c, date('2015-01-01') = localdatetime('2015-01-01T00:00') AS d").to_list()
// #{"a": true, "b": true, "c": (), "d": false}
g.gql("FOR d IN [duration('P1M'), duration('P30DT1S'), duration('PT1H')] RETURN d ORDER BY d").to_list()
// #{"d": duration("PT1H")}, #{"d": duration("P1M")}, #{"d": duration("P30DT1S")}

toString(x) writes a temporal value in Neo4j's text ('12:00', '1984-10-11T12:31', 'PT-1M-0.001S': no zero seconds, trailing fraction zeros stripped, a sign per duration component), while CAST(x AS STRING) writes the engine's canonical ISO 8601 text ('12:00:00', '-PT1M0.001S', Text Formats). The constructors read both back.

g.gql("RETURN toString(localtime('12:00')) AS a, CAST(localtime('12:00') AS STRING) AS b, toString(duration({minutes: -1, milliseconds: -1})) AS c, CAST(duration({minutes: -1, milliseconds: -1}) AS STRING) AS d").to_list()
// #{"a": "12:00", "b": "12:00:00", "c": "PT-1M-0.001S", "d": "-PT1M0.001S"}

Truncation

date.truncate(unit, x [, map]), localtime.truncate(..), time.truncate(..), localdatetime.truncate(..) and datetime.truncate(..) cut x to the start of unit and give a value of their type (these qualified names are Cypher's; GQL has no spelling for them):

FunctionUnits (any ASCII case)
date.truncatemillennium, century, decade, year, weekYear, quarter, month, week, day
localdatetime.truncate, datetime.truncatethose, and hour, minute, second, millisecond, microsecond, nanosecond
localtime.truncate, time.truncateday (midnight) to nanosecond
  • millennium and century follow Neo4j: 2017 truncates to 2000, 1984 to 1900 (Gremlin's date_trunc keeps PostgreSQL's 2001 and 1901). weekYear is the Monday of ISO week 1 of the week-numbering year (1984-01-01 gives 1983-01-03); week is a Monday; nanosecond keeps the value (it holds nanoseconds).
  • x may be of another temporal type and is projected first: the date of a datetime at its own offset, the time of day of either, midnight for a date. datetime.truncate keeps the offset of a datetime (and its zone name: the truncated wall clock is read in that zone again) and gives UTC to a value without one; time.truncate keeps the offset of a time or a datetime.
  • The map overrides fields of the truncated value as the constructors' base form does: {day: 2}, {dayOfWeek: 2}, {hour: 1}, {millisecond: 5}, and for datetime.truncate {timezone: ..}, which keeps the wall clock and reads it in that zone (a name is kept), for time.truncate the offset of the result.
  • A unit the type lacks (date.truncate('hour', ..)) or an unknown unit is 22023; a value without the part the type needs (date.truncate('day', localtime(..))) or a duration 22G03.
g.gql("RETURN date.truncate('millennium', date('2017-10-11')) AS m, date.truncate('century', date('1984-10-11')) AS c, date.truncate('weekYear', date('1984-01-01')) AS wy").to_list()
// #{"c": date("1900-01-01"), "m": date("2000-01-01"), "wy": date("1983-01-03")}
g.gql("RETURN date.truncate('week', date('2017-10-11'), {dayOfWeek: 2}) AS a, localdatetime.truncate('quarter', localdatetime('2017-11-11T12:31:14'), {day: 2}) AS b, localtime.truncate('hour', localtime('12:31:14'), {minute: 5}) AS c").to_list()
// #{"a": date("2017-10-10"), "b": localdatetime("2017-10-02T00:00:00"), "c": time("12:05:00")}
g.gql("RETURN datetime.truncate('month', date('2017-11-11')) AS a, datetime.truncate('day', datetime('2017-10-11T12:31:14+01:00'), {timezone: 'Europe/Stockholm'}) AS b").to_list()
// #{"a": datetime("2017-11-01T00:00:00Z"), "b": datetime("2017-10-11T00:00:00+02:00[Europe/Stockholm]")}
g.gql("RETURN date.truncate('hour', date('2017-10-11')) AS d")   // fails: the unit hour is not defined for a date (22023)

duration.between(a, b)the whole months from a to b (a month counts once its day of the month and time of day are reached), then the whole days after them, then the rest of the time; every part has the sign of the direction

// #{"d": duration("P30Y8M13D"), "dd": duration("P11213D"), "m": duration("P30Y8M"), "s": duration("PT24H")}
g.gql("RETURN duration.between(localdatetime('2015-07-21T21:40:32.142'), date('2015-06-24')) AS a, duration.between(date('1984-10-11'), localtime('16:30')) AS b").to_list()
// #{"a": duration("-P27DT21H40M32.142S"), "b": duration("PT16H30M")}
g.gql("RETURN duration.inDays(localtime('10:00'), localtime('12:00')) AS d")   // fails: two local times have no days (22G03)

Clocks

date(), localtime(), time(), localdatetime() and datetime() with no argument (and their ISO names), the ISO clocks CURRENT_DATE, CURRENT_TIME, CURRENT_TIMESTAMP, LOCAL_TIME and LOCAL_TIMESTAMP (written without parentheses; current_date() with empty ones is accepted too), and X.statement() / X.transaction() (date.statement(), datetime.transaction(), ...) give the time the query started: one instant per query, the same for every row and every call, so a query is deterministic and repeatable. A zone argument or map gives that instant in the zone (datetime.statement('Europe/Berlin'), date({timezone: '+05:00'})); the default zone is UTC. In a script the instant is the script's own: datetime() in g.gql(..) equals the script's now(), and date() its today() at UTC. X.realtime(), a clock that moves while the query runs, is refused like rand().

g.gql("RETURN date() = date.statement() AS a, datetime.transaction() = datetime() AS b, datetime({timezone: '+05:00'}).timezone AS z").to_list()   // #{"a": true, "b": true, "z": "+05:00"}
g.gql("RETURN CURRENT_DATE = date() AS a, CURRENT_TIMESTAMP = zoned_datetime() AS b, LOCAL_TIMESTAMP = local_datetime() AS c").to_list()   // #{"a": true, "b": true, "c": true}
g.gql("FOR i IN [1, 2, 3] RETURN count(DISTINCT datetime()) AS instants").to_list()   // #{"instants": 1}
g.gql("RETURN datetime.realtime() AS t")   // refused: a clock that moves while the query runs

Parameters

$name reads the value of name from the parameter map, the second argument of gql(). A parameter is a value, never query text: it cannot change the query, whatever it holds. A parameter the query reads but the map lacks is an error before the run; extra entries are ignored.

g.gql("MATCH (n:person) WHERE n.age > $min RETURN n.name AS name ORDER BY name", #{min: 30}).to_list()   // #{"name": "josh"}, #{"name": "peter"}
g.gql("MATCH (n:person) WHERE n.name IN $names RETURN n.name AS name, n.age AS age ORDER BY name", #{names: ["josh", "vadas"]}).to_list()
// #{"age": 32, "name": "josh"}, #{"age": 27, "name": "vadas"}
g.gql("MATCH (n:person {name: $who})-[:created]->(s) RETURN s.name AS s", #{who: "peter"}).to_list()   // #{"s": "lop"}
g.gql("MATCH (n:person) RETURN n.name AS name ORDER BY name SKIP $s LIMIT $l", #{s: 2, l: 5}).to_list()   // #{"name": "peter"}, #{"name": "vadas"}

A parameter may also stand where an index can serve it, so MATCH (p:person {name: $n}) uses a property index on person.name when one exists (Plans and Performance).
